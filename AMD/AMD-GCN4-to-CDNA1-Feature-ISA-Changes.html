Feature 与 ISA 变化

从图形与计算共用的 Polaris CU，走向专注 HPC / AI 的 CDNA：新增 Matrix Core、MFMA 与累加寄存器，扩展低精度矩阵计算，同时去除固定功能图形硬件。用 Vega 作为中间参照，明确哪些变化早已发生，哪些由 CDNA1 首次引入。

先对齐 GCN4、gfx803 与手册版本

GCN4 ≠ 名称带“Generation 3”的旧手册，也 ≠ Vega。本报告以 Polaris 为 GCN4。AMD 历史 ROCm 目录将 Generation 3 ISA 手册列作“Fiji 和 Polaris”共同参考；LLVM 同时把 Fiji、Polaris10 / 11 归入 gfx803。因此这里将该手册作为共享 GFX8 ISA 基线，结合 Polaris 白皮书确认范围，不把手册封面的代数当成芯片架构代数。AMD 历史目录：Fiji / Polaris · LLVM 目标与 ABI · AMD Polaris 白皮书（公开备份）

AMD 当前机器可读 ISA 包包含 CDNA1，但没有同口径的 GCN4 XML。下文给出关键指令的逐项证据和完整 CDNA1 XML 清单；旧 PDF 中的名称命中仅用于定位原文。未命中不等于硬件不支持，命中也不证明 MI100 实际可用；本页不发布伪精确的“GCN4 新增 / 删除指令总数”。GPUOpen XML 覆盖范围 · AMD 官方 ISA XML 包

Vega 不是一个完全统一的指令能力点：gfx900 / Vega10 与 gfx906 / Vega20 不同。中间栏主要用 Vega 手册确认既有功能；MI50 的定量值仅引用 CDNA1 白皮书明确给出的比较。

三阶段演进：分清新增、继承与平台变化

GCN4 · Polaris

Wave64、标量 / 向量 CU；已有 FP16 VALU、FP64 指令、DPP / SDWA、LDS。重点改进图形效率、QoS、缓存与 GDDR5 接口。

中间阶段 · Vega

加入 packed FP16 / VOP3P，以及显式 GLOBAL / SCRATCH 等指令。Vega20 / MI50 已有高吞吐 FP64、HBM2 和 GPU 间 IF。

CDNA1 · MI100

矩阵成为原生执行路径：MFMA 支持 FP32 / FP16 / BF16 / INT8，配独立 AGPR；删除固定图形硬件，并扩大 HBM、L2 与互连规模。

普通 FP32 / Matrix FP32

128 / 256

FLOPs/CU/cycle。普通向量 FP32 并未随矩阵路径一起翻倍。

Matrix FP16 / BF16

1,024 / 512

FLOPs/CU/cycle，dense、FP32 累加；两种 16-bit 格式在本代不是同速。

VGPR / AGPR

256 + 256 kB

每 CU 的两个固定物理池。合计 512 kB，不是统一 512 kB 普通 VGPR。

图形功能边界

Compute-only

MI100 手册明确禁用 EXPORT，并禁止 EMIT / CUT；保留名称不代表图形能力。

如何理解寄存器容量与带宽？

GCN 图示可按每 SIMD 256 个 32-bit 向量寄存器 × 64 lanes × 4 B = 64 kB，再乘 4 SIMD 得 256 kB/CU。MI100 的 256 kB VGPR + 256 kB AGPR 是物理池；每线程寄存器上限、每 wave 的占用和分配粒度是另外的约束。没有从“三读一写 × FMA 吞吐”倒算物理 RF 带宽，因为 operand reuse、bank、端口和调度都会改变真实流量。

为什么 CDNA1 白皮书把 MI50 的矩阵 FP16 写成 256？

白皮书脚注明确说明 MI50 没有专用矩阵硬件，该值来自向量执行单元。MI100 的 1,024 是专用 MFMA 路径。相对 Vega packed FP16 为每 CU 4×，相对 Polaris 的单值 FP16 峰值则为 8×；两者分母不同。普通 FP32 为 128→128。比较表及脚注

对内核移植和性能分析的影响

  1. 先确认目标。把 Polaris 的 gfx803 编译目标改为 MI100 的 gfx908，并核对当前工具链实际支持范围。不能将历史 ROCm 支持状态当作当前承诺。
  2. 重新选择矩阵路径。普通向量 GEMM 不会因运行到 MI100 就必然取得 MFMA 峰值；使用针对 gfx908 的库或内核，重新安排 tile、lane 数据布局和 AGPR 占用。
  3. 按数据类型评估。MI100 FP16 MFMA 为 1,024，BF16 为 512；FP32 MFMA 为 256。FMA 数量、格式、精度和累加方式要对齐。
  4. 按资源检查 occupancy。LDS 容量保持 64 kB，矩阵累加引入独立 AGPR 池；总寄存器容量翻倍不保证每个普通向量内核的可用 VGPR 翻倍。
  5. 去除图形依赖。EXPORT、图形 shader 消息、固定图形 / 显示路径不适用于 MI100。保留指令名不是使用许可；以设备限制为准。

如何复现 ISA 索引？

从官方包中取 CDNA1 XML，按 canonical 名称去重并保留 alias、功能组与 encoding / opcode。对每个 canonical 名称，在三个 PDF 的逐页提取文本中执行带名称边界的大小写敏感精确匹配，记录物理页码；不按 miss / hit 判定硬件增删。来源 JSON 保留 URL、获取日期和 SHA-256；报告内嵌完整数据，无需联网即可搜索。GCN4 没有同口径 XML，因此没有计算精确全量跨代 opcode 差分。
