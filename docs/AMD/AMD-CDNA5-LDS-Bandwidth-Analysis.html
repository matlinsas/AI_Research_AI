CDNA5 的 LDS 带宽需求

CDNA5的FP8 / FP4算力相对CDNA4提高约4倍，LDS读带宽最多提高2倍，物理寄存器总容量保持不变。 因此，它对寄存器复用与LDS分区布局的要求更高。

物理寄存器容量没有随寻址范围一起增长。 Wave64变为Wave32后，每SIMD仍为128 kB。以下按WGP计，不换算成假设的CU。

2. 每条WMMA都重新加载A/B，需要多少带宽？

原生尺寸来自ISA；P按MI455X的256 WGP、2.4 GHz和官方dense规格归一化。下面计算达到该格式目标峰值所需的供数下界，不把规格反算成实测指令延迟。

LDS读需求 = P / 2 × (sA/n + sB/m)
输入类型Dense峰值P：ops/WGP/cycle代表性原生m×n×kLDS读需求
FP16/BF168,19216×16×321,024
FP832,76816×16×1282,048
FP6，紧凑32,76816×16×1281,536
FP4，紧凑65,53632×16×1281,536
INT88,19216×16×64512

LDS需求单位：byte/WGP/cycle；暂不计scale。整数使用IOPs，浮点使用FLOPs。FP4列出32×16输出形式。CDNA5 ISA · MI455X 数据手册

例如FP8的16×16×128，A/B共4,096 byte/wave。AMD案例按每条WMMA约8周期建模：

LDS读需求 = 4 × 4,096 / 8 = 2,048 byte/WGP/cycle LDS峰值512 / 需求2,048 = 25%

如果每条WMMA都重新读A/B，仅LDS供数就只能支持约四分之一的目标FP8算力。

8周期来自AMD的FP8简化调度案例，不是所有WMMA的统一实测延迟。MI450 FP8 WMMA 周期模型

3. 扩大wave tile，降低平均读取量

Wave tile是一个wave用多条WMMA负责的输出块。A/B各加载一次后，在这个wave内复用：

LDS读需求 = P / 2 × (sA/Nw + sB/Mw) 平方tile、A/B同类型：LDS读需求 = P × s / Mw
每wave输出tileFP16 / BF16FP8FP6FP4INT8
32×325121,0247681,024256
64×64256512384512128
64×12819238428838496
128×12812825619225664

单位：byte/WGP/cycle，未计scale；未假设跨wave的免费LDS multicast。

64×64的FP8 / FP4，数据本身已用满512；64×128降到384，128×128降到256。

512有分区条件。 SIMD0/2属于Pair A，SIMD1/3属于Pair B。两个pair同时访问不同物理分区，可使用两个256端口；同时访问同一分区会串行化。若持续降至256，64×64的FP8 / FP4只按数据读取就最多支持约50%的目标算力。

同一wave内的同址广播，不能消除两个SIMD pair之间的分区冲突。需要同时调整wave分块、访问顺序与物理分区布局；普通bank swizzle不保证分区分开。

4. VGPR容量能否支持更大的tile？

Wave32下，C/D原地更新只计一份。每lane的32-bit寄存器预算为：

Rc = Mw × Nw / 32 Rab = Kr × (Mw×sA + Nw×sB) / (32×4) Rtotal ≈ Rc + 2×Rab + 16

假设完整A/B双缓冲，另预留16个临时VGPR/lane，按16个寄存器取整。FP16采用Kr＝32，其余采用Kr＝128。

类型64×64总VGPR/laneRF限制waves/SIMD128×128总VGPR/lane对应上限
FP16 / BF1627237841
FP840021,040，放不下—
FP6数据33639121
FP4数据27237841

未计scale寄存器与真实编译器临时值；驻留上限还会受LDS、SGPR及调度等限制。

FP8的128×128完整双缓冲超过预算：

Rc=512，Rab=256 完整双缓冲：512 + 2×256 + 16 = 1,040 > 1,024 改为单缓冲：512 + 256 + 16 = 784

所以128×128并非不能实现，可以改用单缓冲或部分片段预取。

FP4的64×128是较温和的折中：Rc＝256、Rab＝96，总计464 VGPR/lane，约58 kB/wave；仅按RF容量可驻留2 waves/SIMD，数据读取需求为384 byte/WGP/cycle。

5. MX scale与LDS写入还会增加压力

每32个元素一个1-byte scale，且scale也从LDS紧凑加载时：

格式64×6464×128128×128
MXFP8528396264
MXFP6400300200
MXFP4544408272

单位：byte/WGP/cycle。16元素scale分组会使元数据部分翻倍。内联常量scale不需要这些LDS读取。CDNA5 白皮书

64×64的MXFP8 / MXFP4已经超过512，不能按满算力供数。 更大的tile能降低读取量，但scale寄存器也会增加RF占用。

例如FP8四wave按2×2排列，每wave算128×128，workgroup算256×256，LDS每级Kb＝128：

  • A/B逻辑双缓冲容量：128 kB，未计分区分配padding和scale。
  • 满算力A/B读取：256 byte/WGP/cycle。
  • 下一批写入LDS：另需128 byte/WGP/cycle。

Kr是寄存器片段深度，Kb是LDS缓冲深度。TDM / multicast可优化Global→LDS搬运，但不会自动消除LDS→寄存器读取；读峰值也不代表同时还能免费追加写带宽。

6. 分析结论

CDNA5的FP8 / FP4应重点比较64×128与128×128，不能直接沿用64×64。
64×128保留更多寄存器余量；128×128更省LDS读取，但示例通常只剩1 wave/SIMD。

优化顺序可以先检查LDS物理分区和宽读取，再选择wave tile与输入缓冲方式，最后验证WMMA利用率。更大的tile、更多缓冲或更高occupancy，都不必然代表更快。

7. VGPR的带宽需求

扩大wave tile主要降低LDS→VGPR流量；矩阵指令仍要消费A/B和累加器。 下面把寄存器容量问题继续拆成带宽问题。

本节数字是逻辑操作数流量，不是已公布的VGPR物理峰值。 所查AMD白皮书和ISA未给出足以统一核算的RF阵列总读/写峰值。容量、SIMD宽度、源操作数个数，均不足以倒推出全部端口带宽；因此这里不计算“VGPR峰值利用率”。

  • 64个不同C子块合计读64 kB、D写64 kB。

7.4 扩大tile，为什么没有把A/B寄存器读取也同比降下来？

固定16×16×128 FP8 WMMA和目标算力时，wave tile从64×64扩大到128×128，LDS→VGPR输入写入由512降到256 byte/WGP/cycle；逐条WMMA累计的A/B逻辑读仍是2,048。

7.5 CDNA5的A/B reuse hint能改善哪一段？

ISA提供A/B复用提示，让硬件缓存可能被相邻矩阵指令再次消费的输入。常规WMMA使用RA/RB字段；F8F6F4 / F4的复用位放在配套LD_SCALE编码中。它优化的是寄存器操作数供给，不替代跨wave的LDS读取。

FP8 128×128示例中的假设A侧供数B侧供数A/B合计
不扣缓存节省1,0241,0242,048
仅A片段每8次消费读取一次：假设命中1281,0241,152
A/B都实现8次复用：理想流量下界128128256

单位：byte/WGP/cycle。后两行是“如果缓存满足该复用”的供数模型，未声称硬件一定能保存整块128×128的A/B，或能达到对应阵列读数。Hints不改变数学操作数消费量。ISA要求满足相邻指令一致性等条件；误设可能产生未定义结果，不能机械地把所有指令的reuse位置1。CDNA5 ISA · CDNA5 ISA

7.6 结论

128×128 FP8示例：输入写256；A/B逻辑读2,048；C读512；D写512 byte/WGP/cycle。
扩大tile减少了LDS流量；要降低实际RF阵列重复读取，还需匹配指令顺序与合法reuse机制，并验证缓存、旁路和调度效果。

实际优化应检查编译出的矩阵形状、VGPR/AGPR分配、输入复用与spill，再用微基准或性能计数器定位瓶颈。本文给出可复算的逻辑供数预算；物理RF峰值保留为未知。
