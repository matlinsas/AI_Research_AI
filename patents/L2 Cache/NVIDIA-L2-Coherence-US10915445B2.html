01 / TECHNICAL STUDY把远端访问变成可复用的本地命中

US10915445B2 的核心是：为相互配对的缓存增加专用连接，允许请求侧缓存远端内存的数据，并以地址的 home 为一致性归属点维护这些副本。它同时处理访问路径、缓存容量和副本失效三个问题。

题名 Coherent caching of data for high bandwidth scaling 可译为“面向高带宽扩展的数据一致性缓存”。以下以 GPU 分布式 L2 为主要实例；专利的抽象是 processing units、cache 与 memory slices，并不限于某一代产品。

阅读标记：专利披露来自实施例；官方资料来自产品或 ISA 文档；分析推导是解释、成本模型或实验假设。图中“状态成立”指逻辑稳定状态，不能直接当作硬件完成顺序。

技术背景：容量扩大，不保证远端访问按比例变快

当处理单元与内存控制器分布在多个区域时，同一 GPU 内部也可能有“近”和“远”。如果每个缓存只保存直接连接的 memory slice 数据，远端地址每次访问都要经过跨区域互连。大量请求争用共享 crossbar / hub，形成拥塞；更长的导线还会增加物理设计和时序压力。单纯增加 HBM 带宽，并不能解除位于处理单元与数据之间的网络瓶颈。

本专利给出的对策分两步：先让请求进入本侧 partner cache，通过专用连接找 home；再把读回的数据保留为本地副本。第一次读仍可能跨区域，后续读则有机会止于请求侧缓存。代价是多份数据消耗容量，并且写入、替换和共享状态都必须被协调。

路径独立：partner 连接承载数据和一致性命令，减少共享 crossbar / hub 路径上的远端流量；它没有取消 SM 到本侧缓存的通路。

角色按地址区分：唯一 home POC 与请求侧 LCN 可以同时存在；同一缓存对不同地址可分别扮演 POC 和 LCN。

写入按来源区分：LCN 侧写向 POC 传播新数据；home 侧写使 LCN 失效。由此避免把 LCN 误解成完全独立的脏数据所有者。

替换不对称：换出 home 的 POC 数据行，不要求远端 LCN 同时消失；换出 LCN 则涉及 home 共享状态维护。数据驻留与共享关系的寿命必须分别理解。

复制可调节：memory aperture 可关闭 LCN 分配，POC/LCN 可有配额，跟踪表也有容量阈值。这些控制把“是否值得复制”变成资源管理问题。

依据：背景与设计动机、说明书 cols.1–9。以上归纳该方案相对背景架构的主要技术改进。

03 / TECHNICAL STUDYPOC 与 LCN：角色属于缓存行

角色 / 状态含义对读写的影响
POC · Point of Coherence缓存行所属 cache 直接连接该地址的 home memory slice；或由 memory aperture 指定为 home。每份 cache-line 大小的数据具有唯一的 POC 归属；对应的数据行可能暂时不驻留。负责与 home memory 保持一致，并跟踪远端 LCN 共享关系。
LCN · Locally Cached Node在另一个 partner cache 中保存同一地址数据的本地副本。这里的“本地”指请求侧就近可用，原始地址仍属于远端 home。有效读命中可本地完成；写入还需向 POC 传播。
POC，not shared没有有效 LCN 副本，POC 为独占缓存副本。从 home 侧写入时无需使不存在的 LCN 失效。
POC，shared至少一个 partner 中存在共享 LCN。实施例可用计数记录共享副本数量。从 home 侧写入需要发失效消息；带计数的实施例在收齐 ACK 后将共享状态改为 not shared。
LCN，shared / valid已分配的有效副本，可用于服务请求。收到失效后变为无效；不能继续服务请求，可释放或重新分配。
未分配没有有效的 POC/LCN 数据行。需要 miss 处理与分配。

两个方向可以同时成立。对于 home 在 A 的地址 x，A 是 POC、B 是 LCN；对于 home 在 B 的地址 y，B 是 POC、A 是 LCN。每侧的行存储可混合保存 POC 与 LCN，实施例还允许对两类分配数量设置可编程限制。

不要把 POC 读成“目前拿到最新数据的缓存”。它是地址的 home / 一致性归属角色。FIG.1C 的 POC → LCN 是物理缓存槽被另一地址的数据重新使用，不能据此认定同一个地址的 home ownership 在两侧迁移。

“coherent with memory”不等于“每次写立即同步到 HBM”。专利没有给出完整 dirty 状态、写回时点和所有完成条件。可以确认 LCN 写要到达 POC；无法确认 POC 必须采用对 HBM 的 write-through。

来源：cols.3–5，FIG.1B 与 1C。

05 / TECHNICAL STUDY写：LCN 向 POC 更新，POC 使 LCN 失效

在 LCN 一侧发起写入

设 x 的 home 在 B，A 已保存 LCN。A 收到写入后更新本侧 LCN，再通过专用连接发送写命令及新数据，使 B 的 POC 更新。专利说这条 LCN 关系已经在 POC 跟踪，不需要为该关系新增跟踪状态。

A：LCN[x] ← v1 → Dedicated WRITE(x, v1) → B：POC[x] ← v1

在两缓存示例的稳定状态下，两份数据都更新了。LCN 不是可以任意积累脏数据、长期不通知 home 的独立写回副本。但专利没有说明远端写确认之前，源侧何时可让其他请求看到新值，也没有把多 LCN 组中其余副本的写冲突处理完整展开。

在 POC 一侧发起写入

当 B 的本侧处理单元写 x，且 POC 标记 shared，B 通过专用连接发 invalidation，使相关 LCN 无效。若使用共享副本计数，收到同数量的 ACK 后，POC 共享状态清为 not shared；失效的 LCN 不得服务后续请求。

B：home-side WRITE(x, v2) → INVALIDATE(x) → A：LCN[x] invalid → ACK → B：not shared

下次 A 读 x 会 miss，再从 B 得到新数据；允许分配时重新形成 LCN。POC 原来不共享时，就不需要这组远端失效动作。

这不是一份完整 MESI 状态机。专利主要公开 allocated、POC/LCN、shared/not shared 及相应操作，没有给出 M/E/S/I 的完整映射、所有瞬态、竞争仲裁与提交顺序。可以把它理解为具有 home 跟踪的副本协议，但不能把经典 MESI 的规则直接补进去。

原图 FIG.1C：数据槽复用、两类写入与失效（可收起）

原文措辞存在一个局部不一致：FIG.1C step 170 相关文字把新 LCN 状态写成 invalid / not shared，而此前定义有效 LCN 为 allocated、LCN、shared。这里按角色定义、读路径及后续写入语义解释为有效 LCN；该处措辞不用于推导额外协议状态。step 185 也未给出足以还原完整事务来源的时序。

06 / TECHNICAL STUDY最关键的细节：POC 行替换不使 LCN 失效

FIG.2A 区分两条替换路径。它揭示了数据是否驻留与是否存在远端副本并非同一个状态。

选中 POC 数据行

205 选行 → 210 判断为 POC → 235 释放数据行。专利明确：不经专用连接发送命令，即使 partner 中还有 LCN；这些 LCN 仍可服务读和写。相关状态在该槽位再次分配前保持不变。

正确性要求home 侧以后处理写入，仍必须知道哪些 LCN 需要失效。因此共享关系不能因为 POC 数据 SRAM 被替换就立即丢失。专利披露 Cache State 125 可包含用于跟踪共享 LCN 的 n-way associative buffer；但它没有完整说明旧槽位复用后如何保留地址标签、POC miss 如何查跟踪项、状态项何时释放。

合理的实现解释是让共享跟踪寿命独立于数据驻留寿命；这是一项由正确性导出的要求，不是已证实的 A100/Blackwell 目录电路。

这一行为表明远端副本不必与 home 数据行始终同步驻留。它不支持“home 行一替换就向所有远端反向失效”的假设，也不足以推导整个 L1/L2 层次的 inclusion policy。

选中 LCN 数据行

205 选行 → 210 判断非 POC → 215 向 home 发 eviction → 220 home 更新共享状态并回 ACK → 225/230 检查并使其他 LCN 失效 → 235 释放选中行。两缓存 partner set 没有“其他 LCN”，所以后半段不增加额外目标。

专利给出的多 partner 流程会在发现其他 LCN 时也使其失效；不能擅自把它简化成“只减一位 sharer 位”。某实施例仅在专用连接空闲时发送 eviction 命令，说明这些维护动作也需要考虑链路资源。

跟踪容量也会触发失效

即使数据缓存尚有容量，共享 LCN 的跟踪 buffer 也可能先到容量阈值。专利允许此时使一个或多个 LRU LCN 失效，收回跟踪资源。由此可推断：副本命中率不只受 L2 数据容量控制，还可能受共享跟踪容量影响。

来源：FIG.2A steps 205–235 与共享跟踪 buffer 段落。

07 / TECHNICAL STUDY数据容量之外，还有一份共享关系要保存

理解 FIG.2A 的关键不是记住一个状态名称，而是回答：如果 POC 数据已经不在 home，home 下一次写入时如何找到仍有效的远端副本？专利公开了共享跟踪 buffer 与替换行为，却没有给出足以直接实现控制器的全部组织细节。

结构至少要解决的事情披露程度
数据阵列保存本地址的 POC 或远端地址的 LCN 数据；允许两类行竞争空间。Cache Line Storage 118、角色与配额已有说明。
共享跟踪知道某地址还有没有 LCN；失效消息发给谁；计数何时归零。Cache State 125、共享计数、n-way associative buffer 已有说明；不是完整目录格式。
事务与瞬态处理在途填充、写入、失效及 ACK；防止槽位复用后的旧消息影响新地址。属于完整实现必须补齐的部分；没有公开事务 ID、队列或全部状态转换。

容量推导在两缓存、每个远端地址只有一个 LCN 的简化模型中，设 LCN 可用数据容量为 Cᵣ 字节、缓存行为 L 字节，home 共享跟踪最多容纳 D 个不同地址，那么有效远端副本数不超过 min(⌊Cᵣ/L⌋, D)。实际还受组相联冲突、配额和替换策略约束；这里不假定每个跟踪项的具体位数。

一个直接后果是：增加数据 SRAM 未必能增加可保留的远端工作集。如果 D 先满，跟踪项回收导致的失效仍会让副本抖动；反之，D 很大也不能避免数据容量冲突。这两种 miss 原因需要分别测量。

依据：共享跟踪 buffer 与 LRU 失效、POC 数据替换后 LCN 保留。

10 / TECHNICAL STUDY什么时候值得复制一份远端数据？

分析模型以下用于理解设计权衡，不是专利实验结果，也不是量产 GPU 的性能预测。基线已经能通过 partner 连接访问 home，只是不在请求侧保留 LCN；这样可以单独观察“复制”本身的收益。

读重用：一次传输被多少次本地命中摊薄

假设同一远端缓存行在两次失效之间被请求侧读取 r 次，数据响应大小为 L 字节，而且没有容量换出。无 LCN 时跨域读响应为 rL，保留 LCN 时约为 L，可节省 (r−1)L。这一式子只统计读响应 payload，未计请求头、ACK、压缩和争用。

假设每行 128 B无副本有副本读响应字节减少
读取 1 次128 B128 B0%，还占用副本容量
读取 2 次256 B128 B50%
读取 8 次1,024 B128 B87.5%
读取 32 次4,096 B128 B96.875%

128 B 仅是算例参数，不表示本专利或所有 NVIDIA GPU 的一致性粒度；实际 cache line、sector、请求字节数可能不同。

写共享：省掉读流量，同时增加维护流量

home 写可能带来失效命令、ACK 和后续重新填充；LCN 写仍要把更新发送到 home。若多个区域交替读写同一行，LCN 的有效寿命很短，复制收益可能被维护开销抵消。不同线程写同一一致性粒度内的不同字段，也可能出现类似 false sharing 的流量放大；是否发生以及粒度多大，需要实现信息或实验。

容量与链路：复制不会凭空增加唯一数据容量

如果一条数据在多个区域保留副本，物理缓存总容量的一部分存放重复内容；得到的是更近的访问位置，而非同等增长的唯一地址覆盖。专用连接也有带宽和排队限制：它减少共享网络占用，但首次读、LCN 写及维护消息仍可能在 partner 链路上相互竞争。

访问模式预期价值主要限制
远端只读表，频繁重用首次取回后多次本地命中；适合复制。副本工作集必须放得下，且跟踪资源足够。
单次流式扫描几乎没有时间重用；关闭 LCN 可能减少污染。是否有空间局部性、请求合并仍需分析。
生产者偶尔更新，消费者大量读取在两个写入阶段之间可摊薄填充成本。更新频率与每阶段读取次数的比例。
多区域交替写同一行本地读加速有限。写传播、失效、ACK、重填充及排序开销。
本地数据已占满缓存远端副本可能挤掉更有价值的 home 数据。POC/LCN 配额与替换策略。

11 / TECHNICAL STUDY副本一致性不等于程序已经正确同步

Cache coherence关注同一地址的副本如何维护；memory consistency还规定不同地址的读写在不同观察者之间允许怎样的先后关系。POC/LCN 与失效消息说明前者的一种实现框架，却不能单独推出后者的完整规则。

例如，生产者先写数据 payload，再写标志 ready；消费者看到 ready 后再读 payload。即使两条缓存行各自都维持一致性，也不能凭“有 coherent L2”推导消费者必然按期望观察到跨地址顺序。需要使用与通信范围匹配的同步及内存语义；本报告不从协议示意图推导无同步程序的结果。

PTX 文档本次核对的 PTX ISA 8.7 / CUDA 12.8 文档将 cache operator 定义为性能提示，不改变程序内存一致性；其全局数据说明区分了 L2 一致性与多个 L1 之间的行为。因此 .cg 等缓存策略不能代替同步。[T]

从公开方案到可实现控制器，还差哪些关键边界

竞争场景必须保证的技术性质本文的处理
读填充遇到 home 写不能在写完成所需的排序点之后，重新安装已经过期的有效 LCN。共享登记与数据返回需某种序列化、重试或验证；不指定专利没有公开的机制。
home 数据换出后又有写即使数据 miss，仍要处理尚存的远端副本。把共享状态查找与数据命中分开讨论。
旧失效 / ACK 晚到，槽位已复用旧事务不能错误确认或清除新地址、新一轮共享。需要能区分事务；不虚构序号或具体队列设计。
多个 LCN 同时写为同一地址定义冲突顺序，并维护所有有效副本。专利两缓存示例不足以完整说明多写者处理。
原子操作、部分写、脏行换出原子性、字节合并、最新数据保存与内存可见性。这些细节未完整公开；不假设固定执行位置或立即写回 HBM。
拥塞与进度数据、失效和 ACK 相互等待时仍能取得进展。需实现层定义缓冲、流控与资源依赖；专用线本身不自动证明无死锁。

12 / TECHNICAL STUDY与 GPU 产品行为怎么对应？

官方资料NVIDIA 于 2026 年 2 月发布的 Locality Domains 技术文章说明：Ampere、Hopper、Blackwell 旗舰数据中心 GPU 存在内部内存访问距离差异；域内组织 SM、L2 与 DRAM 控制器，Blackwell 的域可对应不同物理 die。文章明确描述了请求侧 L2 缓存远端数据，以减少重复穿越 L2 fabric 的访问。[L]

可以由公开资料支撑仍不能据此确定
一个软件可见的 GPU 内部可以有多个物理访问域；跨域访问有成本。每个域恰好对应专利中的某一 partner set，或每个产品的 slice 配对方式。
请求侧 coherent L2 可保存远端数据，重复读取可能在本侧完成。产品内部一定采用 POC/LCN 名称、全部状态与同样的替换规则。
专利给出一套与这些行为相容的设计。用该专利还原完整量产协议、目录容量或链路消息格式。

因此，适合把本专利当作理解分布式 L2 副本的一种具体架构模型。验证量产实现时，要分别验证拓扑、可观测缓存行为和隐藏协议；相似的外部行为可能由不同控制器实现。

13 / TECHNICAL STUDY相关专利：复制、放置、维护与排序分别解决什么

下表按技术问题选择相关文献，比较副本管理、资源放置、缓存维护和顺序控制。各方案的协议假设与适用层次不同，需要分别理解。

文献核心机制与本专利的关系 / 差异
[R1] WO2018052546A1
AMD · Light-weight cache coherence for data processors with limited data sharing		用 local / remote 区分缓存数据；远端写采用向远端传播的策略。其弱一致性实施例在 acquire 时使本核远端数据副本失效，release 时排空相关远端写缓冲。同样利用数据归属和远端复制；但重点是有限共享场景下同步边界的轻量维护。本专利展开的是 partner 连接上的逐行共享跟踪、更新与失效。
[R2] US20250078199A1
NVIDIA · Unified Memory GPU with Localized Mode		把软件执行位置与关联存储限制在本地连接的 cluster；使用执行 affinity 和内存本地化属性来调节资源放置。本专利让远端数据“读过一次后更近”；localized mode 尽量让计算与数据一开始就近。两者可互补，后者还影响负载均衡和资源可用范围。
[R3] US12417181B1
NVIDIA · Systems and methods for aperture-specific cache operations		记录行所对应的 aperture，执行有选择的 flush / invalidate，使维护操作只影响相关地址类别，例如非一致性系统内存数据。本专利的 aperture 控制是否分配 LCN；该文献关注哪些行需要维护。不能因为都叫 aperture，就把分配策略与维护语义混成一个开关。
[R4] US12566704B2
NVIDIA · Scope tree consistency protocol for cache coherence		按 scope group 组织目录树；利用子节点信息和 PoC token，在符合条件时把一致性管理点移到不同树层。其 PoC 是 scope-group 树中的协议管理角色。本专利按地址 home 定义 POC；FIG.1C 的物理槽位复用不能等同于 scope-tree token 迁移。
[R5] US20260072839A1
NVIDIA · Techniques for directory-ordered release consistency		用 epoch、每目录写入计数和完成跟踪，让目录侧判断 release 所依赖的先前写入是否提交。关注写入顺序与 release 完成条件，补足的是“何时可认为先前操作完成”这一维度；它不替代远端副本的存储与失效策略。

把这些机制放在同一张技术地图里

放置

数据与线程先在哪里？

Localized mode：减少必须跨域的访问，代价可能是更受限制的资源调度。

复制

访问后保留在哪里？

本专利：把远端数据保留成 LCN，以容量和维护流量换本地重用。

维护与顺序

何时失效、何时完成？

Aperture、scope tree、directory-ordered release 分别调节维护对象、协议组织与顺序完成。

14 / TECHNICAL STUDY两篇研究论文补充了什么

HMG · HPCA 2020：拓扑更深时，协议也要分层

HMG: Extending Cache Coherence Protocols Across Modern Hierarchical Multi-GPU Systems 讨论多芯粒 / 多 GPU 层次中的不均匀通信成本，以分层共享跟踪减少昂贵链路流量，并结合有作用域的内存模型简化协议。[W1]

对本专利的启发partner set 是一层局部协作边界；系统扩到多层时，不能只把每个 LCN 的失效广播扁平地放大。共享状态、广播范围和流量应该匹配拓扑。HMG 利用的内存模型假设与本专利不同，不能把它消除某些 ACK 的设计搬到这里；本专利明确存在 ACK 计数实施例。

CARVE · MICRO 2018：片上副本容量不够怎么办？

Combining HW/SW Mechanisms to Improve NUMA Performance of Multi-GPU Systems 提出 CARVE：当远端共享工作集超过片上 LLC 容量时，在 GPU 内存的专用区域缓存远端共享数据，并研究软件数据 / 工作放置与硬件机制的配合。[W2]

对本专利的启发LCN 把数据放进就近片上缓存，强调低延迟；CARVE 把“缓存远端数据”的思路扩到更大的 GPU 内存空间，强调容量。两者说明副本位置是一条容量—访问成本的连续选择，而不是“本地缓存命中”一个二元状态。CARVE 是研究方案，不能据此认定 NVIDIA 产品实现了 DRAM 级 LCN。

问题本专利给出的抓手补充资料帮助思考的扩展
远端重复访问请求侧 LCN。CARVE：工作集大于片上缓存时，还能把副本放在哪里？
网络规模增长partner set 与专用连接。HMG：共享跟踪是否也应该按近远层次组织？
同步与可见性失效 / ACK 的局部规则。PTX：程序的顺序要求取决于内存模型，缓存策略不能独立决定。

15 / TECHNICAL STUDY如何从实验中区分这些机制

以下是由技术分析导出的实验设计，本次未在 GPU 硬件上运行。目的不是通过一条延迟曲线就认定完整 POC/LCN 协议，而是逐项排除替代解释。

问题 / 操作观察量必须排除的干扰
远端首次读取后，重复读取同一工作集首轮与稳态延迟；可获得时观察跨分区 fabric 流量。本侧 L1 命中、home L2 已热、预取、请求合并。仅变快不足以证明请求侧 L2 复制。
先形成远端副本，再定向冲刷 home 数据集远端读取是否仍保留低延迟 / 低跨域流量。冲刷是否真的影响 home 的相关 set，是否也挤掉了远端数据或共享跟踪项。
home 写后同步，再读请求侧是否需要重新填充；新值可见性。使用合法同步，避免把数据竞争、L1 行为与 L2 协议混为一谈。
LCN 侧写后同步，再由 home 读取更新传播成本及 home 读取结果。store 合并、原子序列化、缓存旁路；不能直接用总时间定位唯一执行单元。
增加不同远端地址数，同时控制数据占用失效 / 重填充拐点及共享规模敏感性。数据容量与目录容量可能同时溢出；要结合组映射、访问频率和对照组。
改变读写比例与每次写之间的重用次数吞吐、远端流量和尾延迟随共享强度的变化。时钟、功耗、并发度、内存带宽及调度位置变化。

平台未必公开精确的 L2 slice / home 映射或执行亲和性控制。不能先假定地址映射、再把结果拿来证明这一假定；应记录芯片型号、驱动 / 工具版本、同步方式、访问规模和可验证的放置条件。
